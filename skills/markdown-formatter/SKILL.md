# Markdown 格式化助手

## 一、技能定位

本技能用于**格式化和检查 Markdown 文档**。核心价值：

- 表格对齐：自动计算每列最大宽度，输出整齐对齐的 Markdown 表格
- 目录生成：根据标题层级自动生成可点击的目录（TOC）
- 语法检查：检测未闭合代码块、标题层级跳跃、空链接、重复标题等常见问题
- 文档统计：字数、标题数、段落数、代码块数、表格数、链接数、图片数
- 标题标准化：统一标题空格、层级检查
- 链接检查：检测本地文件链接是否存在
- 多模式：analyze（仅检查）/ format（格式化输出）

## 二、触发场景

当用户出现以下需求时使用本技能：

1. 用户说「帮我格式化一下这个 Markdown」「这个表格对齐一下」
2. 用户说「帮我生成一下文档目录」「给这个 README 加个 TOC」
3. 用户说「检查一下这个 Markdown 有没有语法问题」
4. 用户说「帮我统计一下这篇文档的字数/结构」
5. 用户说「这个 Markdown 表格太乱了，帮我整理一下」
6. 用户说「帮我美化一下这个文档」
7. 用户说「检查一下这个文档里的链接有没有断的」
8. 用户提供 .md 文件，要求"整理""格式化""检查"

## 三、支持的检查项

### 3.1 语法问题

| 问题 | 说明 | 严重度 |
|---|---|---|
| 未闭合代码块 | ``` 数量为奇数 | 高 |
| 标题层级跳跃 | 从 H1 直接跳到 H3 | 中 |
| 空链接 | `[文字]()` 链接为空 | 中 |
| 重复标题 | 同一层级有相同标题 | 低 |
| 空标题 | `## ` 后面没有文字 | 中 |
| 表格列数不一致 | 表格行的列数不同 | 高 |
| 表格缺少分隔行 | 表头后没有 `|---|` 行 | 高 |

### 3.2 格式问题

| 问题 | 说明 |
|---|---|
| 表格未对齐 | 列宽不一致，视觉不整齐 |
| 标题前后空行 | 标题前后缺少空行 |
| 列表缩进不一致 | 列表项缩进混乱 |
| 代码块语言未指定 | ``` 后没有语言标识 |

### 3.3 文档统计

| 指标 | 说明 |
|---|---|
| 总字数 | 中文字符 + 英文单词数 |
| 标题数 | 各级标题数量 |
| 段落数 | 非空文本段落数 |
| 代码块数 | ``` 包裹的代码块数 |
| 表格数 | Markdown 表格数 |
| 链接数 | `[文字](url)` 链接数 |
| 图片数 | `![alt](url)` 图片数 |
| 列表项数 | 有序/无序列表项数 |

## 四、操作步骤

### 步骤 1：接收 Markdown 文件

确认用户输入的 .md 文件路径，或直接粘贴的 Markdown 文本。

### 步骤 2：运行格式化脚本

使用 `scripts/format_markdown.py` 进行处理：

```bash
# 仅分析（检查问题 + 统计）
python3 scripts/format_markdown.py --file doc.md --mode analyze

# 格式化（输出对齐后的表格和标准化内容）
python3 scripts/format_markdown.py --file doc.md --mode format

# 格式化并写入新文件
python3 scripts/format_markdown.py --file doc.md --mode format --output formatted.md

# 生成目录
python3 scripts/format_markdown.py --file doc.md --toc

# 检查本地链接
python3 scripts/format_markdown.py --file doc.md --check-links

# 从 stdin 读取
cat doc.md | python3 scripts/format_markdown.py --mode analyze
```

### 步骤 3：解读分析结果

脚本输出包含：

```
📊 Markdown 文档分析报告
━━━━━━━━━━━━━━━━━━
文件：doc.md

📈 统计信息：
  总字数：1,234
  标题数：12（H1:1, H2:5, H3:6）
  段落数：28
  代码块数：4
  表格数：2
  链接数：8
  图片数：1
  列表项数：15

⚠ 发现的问题：
  1. [高] 第15行：表格列数不一致（表头3列，数据行2列）
  2. [中] 第8行：标题层级跳跃（H1 → H3）
  3. [中] 第22行：空链接 [点击这里]()
  4. [低] 第5行和第12行：重复标题"使用方法"

✅ 建议：
  - 修复表格列数不一致
  - 在 H1 和 H3 之间添加 H2
  - 补充空链接的 URL
```

### 步骤 4：格式化输出（如需要）

如果用户要求格式化，脚本会：
1. 对齐所有表格的列宽
2. 标准化标题格式（# 后加空格）
3. 在标题前后添加空行
4. 输出格式化后的 Markdown

### 步骤 5：生成目录（如需要）

根据标题层级生成可点击的目录：

```
## 目录
- [简介](#简介)
- [安装](#安装)
  - [依赖](#依赖)
  - [配置](#配置)
- [使用方法](#使用方法)
```

## 六、常见场景处理

### 场景 1：表格对齐
**用户**：「这个 Markdown 表格太乱了，帮我对齐一下」
**处理**：运行 format 模式 → 自动计算每列最大宽度 → 输出对齐后的表格。

### 场景 2：生成目录
**用户**：「帮我给这个文档加个目录」
**处理**：提取所有标题 → 按层级生成锚点链接 → 输出 TOC。

### 场景 3：语法检查
**用户**：「检查一下这个 Markdown 有没有问题」

### 场景 4：文档统计
**用户**：「帮我统计一下这篇文档的字数和结构」

### 场景 5：整体美化

## 七、注意事项

1. **不修改原始文件**：格式化结果输出到新文件或 stdout，原始文件保持不变。
2. **表格对齐是视觉优化**：不改变表格内容，只调整空格对齐。
3. **目录锚点规则**：GitHub 风格锚点（小写、空格转连字符、移除特殊字符）。
4. **中文字数统计**：中文字符按字数计，英文按单词数计。
5. **链接检查范围**：只检查本地文件链接（相对路径），不检查远程 URL。
6. **代码块不格式化**：代码块内的内容保持原样，不做格式化。
7. **标题层级建议**：文档应以一个 H1 开头，层级不跳跃。
8. **大文件处理**：超过 10 万行的文件可能需要较长时间。
9. **编码假设**：假设文件为 UTF-8 编码。
10. **不替代专业工具**：复杂的 Markdown 处理（如数学公式、Mermaid 图表）建议使用专业编辑器。
