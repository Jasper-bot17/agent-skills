# 任务优先级排序助手

## 一、技能定位

本技能用于**帮助用户从一堆待办事项中理清优先级**。核心价值：

- 艾森豪威尔矩阵：自动按"紧急×重要"将任务分到四个象限
- 智能评分：综合截止日期、预计耗时、依赖关系、任务影响度计算优先级分数
- 执行顺序：输出推荐的执行顺序，避免"先做容易的事"陷阱
- 时间分配：根据工作时间总量，给出每日/每时段的时间分配建议
- 一键导入：从纯文本或 CSV 快速导入待办事项
-  actionable：不是泛泛的"四象限图"，而是具体到"今天先做哪个、花多久"

## 二、触发场景

当用户出现以下需求时使用本技能：

1. 用户说「我有一堆事要做，不知道先做哪个」「帮我排个优先级」
2. 用户说「今天/这周任务太多了，帮我理一理」
3. 用户说「帮我用四象限法分类一下这些任务」
4. 用户说「这些待办哪些该立即做，哪些可以延后」
5. 用户说「帮我做个今日计划/本周计划」
6. 用户说「我太忙了，帮我看看哪些可以不做或委托」
7. 用户说「帮我排一下工作顺序」「这个任务和那个任务哪个先做」
8. 用户给出一串待办事项，要求排序或分类

## 三、核心方法：艾森豪威尔矩阵

### 四象限分类

| | **紧急** | **不紧急** |
|---|---|---|
| **重要** | **Q1 立即做** | **Q2 计划做** |
| | 截止日期今天/明天 | 有截止日期但较远 |
| | 阻塞他人/项目 | 长期价值、规划、学习 |
| | 危机处理 | 预防、关系建设 |
| **不重要** | **Q3 委托做** | **Q4 删除/减少** |
| | 紧急但不影响目标 | 忙碌但无价值 |
| | 部分会议、邮件 | 无意义刷手机、无效会议 |
| | 可委托他人 | 可直接不做 |

### 分类原则

- **重要**：是否影响核心目标、关键结果、长期价值
- **紧急**：是否有近期截止日期、是否阻塞他人、是否有时间压力
- 不要把"紧急"等同于"重要"——这是优先级判断最常见的错误

## 四、任务评分模型

脚本使用综合评分（0-100），加权计算：

| 维度 | 权重 | 说明 |
|---|---|---|
| 截止日期临近度 | 35% | 距截止日期越近分数越高（今天=100，7天=50，30天=20，无截止=10） |
| 重要度 | 30% | 用户标注的重要程度（高=100/中=60/低=30） |
| 紧急度 | 20% | 用户标注的紧急程度（立即=100/本周=60/本月=30） |
| 耗时惩罚 | 10% | 耗时越长分数越低（>2小时扣分，防止拖延困难任务） |
| 阻塞他人 | 5% | 是否阻塞其他任务或同事（是=+20分） |

## 五、操作步骤

### 步骤 1：收集待办事项

从用户输入中提取任务列表。支持多种输入格式：

**纯文本列表**：
```
完成季度报告（周五截止，重要）
回复客户邮件（今天内）
准备下周三的演示
和团队同步进度
```

**CSV 文件**：
```csv
任务,重要度,紧急度,预计耗时,截止日期,备注
完成季度报告,高,本周,3小时,2026-09-20,
回复客户邮件,中,今天,30分钟,,客户在等
准备演示,高,本月,2小时,2026-09-25,
```

**一句话描述**：
```
我现在有：写周报、修一个 bug、回复三条消息、准备明天的会议、报销上个月的发票
```

### 步骤 2：运行排序脚本

使用 `scripts/prioritize_tasks.py` 进行分析：

```bash
# 从文本文件读取任务
python3 scripts/prioritize_tasks.py --file tasks.txt

# 从 CSV 读取任务（带结构化信息）
python3 scripts/prioritize_tasks.py --file tasks.csv --format csv

# 直接传入任务列表
python3 scripts/prioritize_tasks.py --task "完成季度报告" --task "回复客户邮件" --task "准备演示"

# 指定每日可用工作时间（默认8小时）
python3 scripts/prioritize_tasks.py --file tasks.txt --work-hours 6

# 从 stdin 读取
cat tasks.txt | python3 scripts/prioritize_tasks.py

# 输出 JSON 格式（便于二次处理）
python3 scripts/prioritize_tasks.py --file tasks.csv --format csv --output json
```

### 步骤 3：解读分类结果

脚本输出包含：

```
📋 任务优先级分析报告
━━━━━━━━━━━━━━━━━━
总任务数：8 | 总预计耗时：12.5小时
每日可用时间：6小时

🟥 Q1 立即做（2个，共2.5小时）：
  1. 回复客户邮件 [30分钟] [今天截止]
     → 客户在等，阻塞项目进度
  2. 修登录bug [2小时] [紧急]
     → 阻塞所有用户登录

🟧 Q2 计划做（3个，共7小时）：
  3. 完成季度报告 [3小时] [周五截止]
  4. 准备演示 [2小时] [下周三]
  5. 写周报 [1小时] [本周五]

🟨 Q3 委托/快做（2个，共1小时）：
  6. 回复三条消息 [30分钟]
  7. 报销发票 [30分钟]

🟩 Q4 删除/延后（1个）：
  8. 整理桌面文件夹
     → 无明确价值，延后或不做

⏱ 今日执行建议（6小时）：
  上午（3小时）：
    1. 回复客户邮件（30分钟）
    2. 修登录bug（2小时）
    3. 写周报（30分钟）
  下午（3小时）：
    4. 完成季度报告（3小时）
```

### 步骤 4：与用户确认调整

根据脚本结果，与用户确认：

1. **分类是否合理**：有没有任务放错象限？用户对重要度/紧急度的判断是否和脚本一致？
2. **截止日期是否准确**：有没有遗漏的截止日期？
3. **耗时估计是否合理**：任务估计耗时是否需要调整？
4. **哪些可以委托/删除**：Q3/Q4 任务是否真的可以不做或交给别人？

### 步骤 5：输出最终计划

根据用户反馈调整后，输出最终的：
- 今日/本周执行顺序
- 每段时间做什么
- 哪些任务可以不做
- 哪些任务需要委托

## 七、常见场景处理

### 场景 1：任务太多不知道从哪开始
**用户**：「我今天有10件事要做，完全不知道从哪开始」
**处理**：收集所有任务 → 脚本评分排序 → 输出 Q1 任务和今日执行建议 → 帮用户聚焦最紧急的 2-3 件事。

### 场景 2：用四象限法分类
**用户**：「帮我用四象限法把这些任务分一下」
**处理**：按紧急×重要分到四个象限 → 标注每类任务的处理策略 → 给出建议。

### 场景 3：识别可以不做的事
**用户**：「我是不是太忙了？哪些可以不做？」
**处理**：分析 Q4 象限 → 识别低价值任务 → 建议删除、延后或委托 → 减轻负担。

### 场景 4：制定每日计划
**用户**：「帮我做个今天的工作计划」
**处理**：输入待办和可用时间 → 脚本生成时间段分配 → 输出上午/下午各做什么。

### 场景 5：判断两个任务哪个先做
**用户**：「我应该先写报告还是先回邮件？」
**处理**：分析两个任务的截止日期、阻塞关系、耗时 → 给出排序建议和理由。

## 八、注意事项

1. **不替用户做决策**：脚本给出建议，最终判断由用户做。如果用户对分类有不同看法，以用户为准。
2. **重要度需用户确认**：脚本根据关键词推断重要度（如"老板""客户""截止"），但可能不准确，需与用户确认。
3. **避免分析瘫痪**：任务超过 15 个时，建议先只看 Q1，不要被全部分类淹没。
4. **预留缓冲时间**：实际执行时间通常比预估长，建议计划时间打 8 折，预留缓冲。
5. **Q2 是重点**：高效人士把时间主要花在 Q2（重要不紧急），而不是一直救火 Q1。
6. **定期清理 Q4**：每周检查一次 Q4，主动删除低价值任务。
7. **不要同时做太多**：一次专注一个任务，批量处理 Q3 小任务。
8. **任务粒度**：超过 2 小时的任务建议拆分成子任务。
9. **不是 productivity 教条**：这是辅助工具，不是生活方式指导。
10. **用户偏好优先**：如果用户有特定的做事习惯（如先做简单的），在脚本基础上调整。
