# CSV 数据清洗助手

## 一、技能定位

本技能用于**自动检测和修复 CSV/TSV 表格数据中的常见质量问题**。核心价值：

- 全面检测：重复行、缺失值、空行、空格污染、大小写不一致、异常值、格式不统一
- 安全修复：dry-run 预览 → 确认后执行，不破坏原始数据
- 智能处理：自动识别列类型（数值/文本/日期/布尔），按类型选择合适的清洗策略
- 完整报告：清洗前后对比、问题统计、每列修复动作明细
- 零依赖：纯 Python 标准库，无需 pandas/openpyxl 等外部依赖

## 二、触发场景

当用户出现以下需求时使用本技能：

1. 用户说「帮我清洗一下这个 CSV」「这个表格数据太乱了，帮我整理」
2. 用户说「帮我检查一下这个 CSV 有什么问题」
3. 用户说「这个 CSV 有重复行/空值，帮我清理」
4. 用户说「导出的数据格式不统一，帮我标准化」
5. 用户说「数据分析前帮我把数据预处理一下」
6. 用户提供 CSV 文件路径或内容，要求「清洗」「整理」「去重」「补全缺失值」

## 三、检测的问题类型

### 3.1 结构问题

| 问题 | 说明 | 严重度 |
|---|---|---|
| 空行 | 完全为空的行 | 低 |
| 列数不一致 | 某行字段数与表头不匹配 | 高 |
| 表头缺失 | 文件没有列名 | 中 |
| BOM 头 | UTF-8 BOM 导致首列名异常 | 低 |

### 3.2 重复问题

| 问题 | 说明 | 严重度 |
|---|---|---|
| 完全重复行 | 所有列值完全相同 | 高 |
| 近似重复行 | 关键字段相同，其他字段略有差异 | 中 |

### 3.3 缺失值问题

| 问题 | 说明 | 严重度 |
|---|---|---|
| 空单元格 | 值为空字符串或 null/NA/N/A | 中 |
| 整行缺失率过高 | 某行超过 50% 的列为空 | 高 |
| 整列缺失率过高 | 某列超过 50% 的值为空 | 中 |

### 3.4 格式问题

| 问题 | 说明 | 严重度 |
|---|---|---|
| 前后空格 | 值首尾有空格（如「 北京 」） | 中 |
| 大小写不一致 | 如「Beijing」「beijing」「BEIJING」混用 | 中 |
| 日期格式不统一 | 如「2024-01-15」「2024/1/15」「01-15-2024」混用 | 中 |
| 数值混入文本 | 数值列中有「N/A」「未知」「」等非数值 | 中 |
| 数值格式不统一 | 如「1,000」「1000」「1.000」混用 | 低 |

### 3.5 异常值问题

| 问题 | 说明 | 严重度 |
|---|---|---|
| 数值离群点 | 超出均值±3标准差的极端值 | 低（仅报告） |
| 文本列异常长值 | 超过平均长度3倍的值 | 低（仅报告） |

## 四、清洗操作

### 4.1 默认执行的清洗

| 操作 | 说明 |
|---|---|
| 删除空行 | 完全为空的行直接删除 |
| 去除首尾空格 | 所有文本值 strip() |
| 统一大小写选项 | 可选：标题化/全小写/全大写 |
| 删除完全重复行 | 保留首次出现的行 |
| 标准化日期 | 识别常见日期格式，统一为 YYYY-MM-DD |
| 数值列清洗 | 去除千分位逗号，转换为数值；非数值值标记为缺失 |
| 清理 BOM | 移除 UTF-8 BOM 头 |

### 4.2 缺失值处理策略

| 策略 | 说明 | 适用 |
|---|---|---|
| `drop` | 删除含缺失值的行 | 缺失少、不能估算 |
| `fill_na` | 填充为 `N/A` 或用户指定值 | 文本列 |
| `fill_mean` | 填充为列均值 | 数值列 |
| `fill_median` | 填充为列中位数 | 数值列（有离群点时） |
| `forward` | 前向填充（用上一个有效值） | 时间序列 |
| `ignore` | 不处理，保留原样 | 仅检测不清洗 |

### 4.3 清洗模式

| 模式 | 说明 |
|---|---|
| `analyze` | 仅检测问题，不修改数据 |
| `dry-run` | 预览清洗方案，输出清洗后数据但不写文件 |
| `execute` | 实际执行清洗，输出清洗后文件和报告 |

## 五、操作步骤

### 步骤 1：接收数据文件

1. 确认 CSV 文件路径（必须是本地文件路径）
2. 检测分隔符（自动识别逗号/制表符/分号）
3. 检测编码（UTF-8/GBK/Latin-1）
4. 读取表头和数据行
5. 如果数据量很大（>10000行），告知用户处理时间

### 步骤 2：运行检测脚本

使用 `scripts/clean_csv.py` 进行检测和清洗：

```bash
# 仅分析（检测问题，不修改）
python3 scripts/clean_csv.py --input data.csv --mode analyze

# 预览清洗方案（dry-run）
python3 scripts/clean_csv.py --input data.csv --mode dry-run

# 执行清洗
python3 scripts/clean_csv.py --input data.csv --mode execute --output cleaned.csv

# 指定缺失值处理策略
python3 scripts/clean_csv.py --input data.csv --mode execute --missing-strategy fill_na

# 删除完全重复行
python3 scripts/clean_csv.py --input data.csv --mode execute --remove-duplicates

# 去除首尾空格
python3 scripts/clean_csv.py --input data.csv --mode execute --trim-whitespace

# 自动检测编码和分隔符
python3 scripts/clean_csv.py --input data.csv --mode analyze
```

### 步骤 3：解读检测结果

脚本输出包含：

```

⚠ 发现的问题：
  1. 5 行完全重复

  3. "部门"列有大小写不一致：研发/研发部/R&D
  4. "年龄"列有2个非数值值：'未知', 'N/A'

  - 用中位数填充年龄缺失值
```

### 步骤 4：确认清洗策略

根据检测结果和用户需求，确认清洗策略：

1. **是否删除重复行？** 默认删除完全重复行，近似重复行需用户确认
2. **缺失值如何处理？** 根据列类型推荐策略：
   - 数值列：中位数填充（抗离群）
   - 文本列：填充为 "N/A" 或删除
   - 日期列：前向填充或删除
3. **是否去除首尾空格？** 默认去除
4. **是否统一日期格式？** 默认统一为 YYYY-MM-DD
5. **异常值如何处理？** 默认仅报告不处理（不轻易删除数据）

### 步骤 5：执行清洗

1. 运行清洗脚本（execute 模式）
2. 输出清洗后的数据文件（CSV 格式）
3. 生成清洗报告（清洗前后对比）
4. 原始数据不修改，清洗后数据另存

### 步骤 6：交付结果

输出：
1. **清洗后 CSV 文件**：`cleaned.csv`
2. **清洗报告**：统计清洗前后对比
3. **修改摘要**：每列做了什么操作

## 七、常见场景处理

### 场景 1：导出数据去重
**用户**：「这是从系统导出的 CSV，有重复行，帮我清理」
**处理**：检测重复行 → dry-run 预览 → 确认后删除重复行 → 输出清洗后文件。

### 场景 2：实验数据预处理
**用户**：「实验数据有缺失值和异常值，帮我预处理一下」
**处理**：检测缺失值分布 → 数值列用中位数填充 → 异常值仅报告不删除（标记） → 输出清洗后数据。

### 场景 3：数据格式统一
**用户**：「这个 CSV 日期格式乱七八糟，帮我统一」
**处理**：检测日期列的各种格式 → 统一为 YYYY-MM-DD → 报告转换了多少个值。

### 场景 4：仅检测不修改
**用户**：「帮我看看这个 CSV 有什么问题，先不要改」
**处理**：analyze 模式 → 输出问题列表和建议 → 不修改数据。

### 场景 5：多列缺失值处理
**用户**：「帮我把这个 CSV 的缺失值都处理一下」
**处理**：分析每列缺失率和类型 → 数值列中位数填充 → 文本列填充 "N/A" → 输出清洗后文件。

## 八、注意事项

1. **不修改原始文件**：清洗后数据另存为新文件，原始文件保持不变。
2. **异常值不自动删除**：异常值仅报告，不自动删除（避免误删真实数据）。
3. **近似重复需确认**：完全重复行可自动删除，近似重复行需用户确认。
4. **大文件处理**：超过 10 万行的文件，告知用户可能需要较长时间。
5. **编码检测**：自动检测 UTF-8/GBK/Latin-1，检测失败时提示用户指定编码。
6. **列类型推断**：基于采样（前100行）推断列类型，可能有误差。
7. **保留表头**：清洗不修改表头行。
8. **不替代专业数据工具**：复杂数据清洗（如正则替换、业务规则）建议结合 AI 语义处理。
9. **隐私保护**：不读取文件以外的数据，清洗过程在本地完成。
10. **备份原始数据**：建议用户在清洗前备份原始文件。
