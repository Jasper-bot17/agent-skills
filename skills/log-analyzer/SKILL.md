# 日志分析助手

## 一、技能定位

本技能用于**快速分析和诊断日志文件**。核心价值：

- 自动解析多种日志格式，无需手动配置
- 一眼看清日志级别分布和错误趋势
- 自动识别高频错误和异常模式
- 按时间范围过滤，定位特定时段的问题
- 检测错误突增（异常检测）
- 生成结构化分析报告

## 二、触发场景

当用户出现以下需求时使用本技能：

1. 用户说「帮我分析一下这个日志」「这个日志里有什么错误」
2. 用户说「帮我看看服务器日志」「应用报错了帮我查查」
3. 用户说「统计一下日志里各有多少 ERROR/WARN」
4. 用户说「找出日志里的高频错误」「最近有什么异常」
5. 用户说「帮我过滤某个时间段的日志」
6. 用户说「这个日志文件太大了，帮我总结一下」
7. 用户提供日志文件或日志内容，要求"分析""排查""检查"

## 三、支持的日志格式

| 格式 | 说明 | 自动识别 |
|---|---|---|
| 纯文本日志 | 每行一条，包含级别关键字 | ✅ |
| JSON 日志 | 每行一个 JSON 对象 | ✅ |
| Nginx access log | 标准 Nginx 访问日志 | ✅ |
| Apache access log | 标准 Apache 访问日志 | ✅ |
| syslog | Linux 系统日志 | ✅ |
| 自定义格式 | 包含时间戳和级别即可 | ✅ |

## 四、分析功能

### 4.1 日志级别统计

自动识别并统计以下级别：
- **FATAL / CRITICAL**：致命错误
- **ERROR / ERR**：错误
- **WARN / WARNING**：警告
- **INFO**：信息
- **DEBUG / TRACE**：调试
- **UNKNOWN**：无法识别的行

### 4.2 错误分析

- 统计每个错误消息的出现次数
- 按频率排序，找出 Top N 高频错误
- 提取错误堆栈的关键信息
- 识别重复出现的异常类型

### 4.3 时间分析

- 识别日志中的时间戳格式
- 统计日志时间范围（最早/最晚）
- 按小时/分钟统计日志量
- 检测错误突增时段

### 4.4 异常检测

- 对比各时段错误率
- 标记错误量显著高于平均的时段
- 识别突然出现的新错误类型

### 4.5 过滤功能

- 按日志级别过滤（只看 ERROR 以上）
- 按时间范围过滤
- 按关键词过滤
- 支持组合条件

## 五、操作步骤

### 步骤 1：接收日志数据

确认用户输入的日志来源：
- 日志文件路径
- 直接粘贴的日志内容
- 压缩的日志文件（.gz/.zip）

### 步骤 2：运行分析脚本

使用 `scripts/analyze_log.py` 进行分析：

```bash
# 基本分析（统计+错误Top10）
python3 scripts/analyze_log.py --file app.log

# 只看错误和警告
python3 scripts/analyze_log.py --file app.log --level ERROR,WARN

# 按时间范围过滤
python3 scripts/analyze_log.py --file app.log --from "2026-09-28 10:00" --to "2026-09-28 12:00"

# 显示更多错误详情
python3 scripts/analyze_log.py --file app.log --top 20

# 按关键词过滤
python3 scripts/analyze_log.py --file app.log --grep "TimeoutException"

# 输出 JSON 格式报告
python3 scripts/analyze_log.py --file app.log --format json

# 从 stdin 读取
cat app.log | python3 scripts/analyze_log.py
```

### 步骤 3：解读分析结果

根据报告重点关注：
1. **级别分布**：ERROR/FATAL 占比是否过高
2. **高频错误**：Top N 错误是什么，出现多少次
3. **时间趋势**：哪个时段错误突增
4. **异常检测**：是否有异常时段标记
5. **首次出现**：是否有新的错误类型

### 步骤 4：给出排查建议

根据分析结果：
- 高频错误 → 建议优先修复
- 错误突增 → 建议检查对应时段的部署/变更
- 特定异常 → 给出可能的原因和排查方向

## 七、常见场景处理

### 场景 1：应用报错排查
**用户**：「应用今天下午报错很多，帮我分析日志」
**处理**：运行分析 → 聚焦 ERROR/FATAL → 按时间过滤下午时段 → 找出高频错误 → 给出排查建议。

### 场景 2：日常运维巡检
**用户**：「帮我看看昨天的服务器日志有没有异常」
**处理**：运行分析 → 查看级别分布 → 异常检测 → 输出报告。

### 场景 3：性能问题定位
**用户**：「系统最近很慢，日志里能看出什么吗」
**处理**：运行分析 → 关注超时错误 → 按时间统计 → 找出慢请求集中时段。

### 场景 4：日志审计
**用户**：「帮我统计这个月日志里各类型错误的数量」
**处理**：运行分析 → 级别统计 + 错误分类 → 输出汇总。

## 八、注意事项

1. **大文件处理**：超过 500MB 的日志文件建议先按时间切割再分析。
2. **编码假设**：假设日志文件为 UTF-8 编码，其他编码可能乱码。
3. **时间戳格式**：自动识别常见格式（ISO 8601、yyyy-MM-dd HH:mm:ss、MMM dd HH:mm:ss 等），无法识别时不做时间分析。
4. **JSON 日志**：每行必须是完整 JSON，混合格式会按纯文本处理。
5. **隐私保护**：日志内容不离开本地，分析过程在本地完成。
6. **不修改原文件**：分析结果输出到 stdout，原始日志保持不变。
7. **错误推断**：排查建议基于常见模式推断，具体原因需结合代码和环境确认。
8. **采样分析**：超大文件可使用 `--sample` 参数随机采样分析。
