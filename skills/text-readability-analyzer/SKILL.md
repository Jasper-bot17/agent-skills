# 文本可读性分析助手

## 一、技能定位

本技能用于**量化分析文本质量并给出可操作的改进建议**。核心价值：

- 多维度量化指标：字数、句长、段长、阅读时间、词汇复杂度
- 自动定位问题：过长句子、重复用词、填充词、被动句、冗长表达
- 可读性评分：综合评分 + 分项雷达式评估
- 具体改进建议：不仅指出问题，还给出修改方向和示例
- 中英文双支持：中文按字/词分析，英文按词/音节分析
- 适配多种文体：公文、学术、公众号、技术文档、商业文案

## 二、触发场景

当用户出现以下需求时使用本技能：

1. 用户提供一段文本，说「帮我看看这段文字写得怎么样」「分析一下这段文字」
2. 用户说「帮我润色一下这段文字」「这段文字有什么问题」
3. 用户说「帮我检查一下文章可读性」「这段文字好懂吗」
4. 用户说「我的文章太长了，帮我看看哪里可以精简」
5. 用户说「帮我分析一下这篇公众号文章的写作质量」
6. 用户说「这段文字有多少字？读多久？」
7. 用户说「帮我看看有没有重复用词」
8. 用户写完报告/邮件/文章后说「帮我检查一下」

## 三、分析维度体系

### 3.1 基础统计

| 指标 | 说明 | 健康参考值（中文） |
|---|---|---|
| 总字符数 | 去除空白后的字符数 | — |
| 总字数 | 中文按字、英文按词 | — |
| 句子数 | 按句号/问号/叹号/分号分割 | — |
| 段落数 | 按换行分割 | — |
| 平均句长 | 总字数 / 句子数 | 15-30 字为佳 |
| 平均段长 | 总字数 / 段落数 | 100-300 字为佳 |
| 阅读时间 | 总字数 / 阅读速度 | 中文约 300 字/分钟 |

### 3.2 句子质量

| 指标 | 说明 | 预警阈值 |
|---|---|---|
| 长句数量 | 超过 40 字的句子 | 占比 > 20% |
| 超长句数量 | 超过 60 字的句子 | 占比 > 5% |
| 短句数量 | 少于 8 字的句子 | 过多（>30%）也需注意 |
| 句长变异系数 | 句长标准差/均值，反映节奏变化 | < 0.5 为节奏单一 |

### 3.3 词汇与表达

| 指标 | 说明 | 关注点 |
|---|---|---|
| 高频词 Top 20 | 出现频率最高的词 | 检查是否过度重复 |
| 重复词组 | 连续出现或高频重复的短语 | 避免啰嗦 |
| 填充词检测 | 「的」「了」「是」「进行」「相关」等 | 过多影响简洁度 |
| 被动句检测 | 「被」「受」「为…所」「由…所」 | 过多显得生硬 |
| 冗长表达 | 「由于…的原因」「在…方面」「对于…来说」 | 可精简 |

### 3.4 可读性评分（0-100）

综合以下因素计算：

- 句子长度合理性（30%）：平均句长是否在合理范围
- 句子变化性（15%）：句长是否有节奏变化
- 段落结构合理性（15%）：段落是否过长或过碎
- 词汇丰富度（20%）：是否有过度重复的词
- 表达简洁度（20%）：填充词和冗长表达的比例

| 分数区间 | 等级 | 含义 |
|---|---|---|
| 90-100 | A | 优秀，表达清晰流畅 |
| 75-89 | B | 良好，少量可改进 |
| 60-74 | C | 一般，有明显改进空间 |
| 40-59 | D | 较差，需重点修改 |
| 0-39 | E | 很差，建议重写部分内容 |

## 四、操作步骤

### 步骤 1：接收文本并确认分析需求

1. 读取用户提供的文本（直接粘贴、文件路径、或对话中的段落）
2. 确认文体类型（如用户未说明，根据内容自动判断）：
   - 公文/正式报告
   - 学术论文
   - 公众号/新媒体文章
   - 技术文档
   - 商业文案/营销
   - 日常沟通/邮件
3. 确认是否需要：
   - 完整分析报告
   - 仅问题列表
   - 润色建议（直接给出修改后的文本）

### 步骤 2：运行辅助分析脚本

使用 `scripts/analyze_readability.py` 进行量化分析：

```bash
# 分析文本文件（默认文本输出）
python3 scripts/analyze_readability.py --input article.txt

# 分析并指定文体
python3 scripts/analyze_readability.py --input article.txt --style academic

# JSON 格式输出（便于程序处理）
python3 scripts/analyze_readability.py --input article.txt --format json

# 从 stdin 读取
echo "这是一段测试文本。" | python3 scripts/analyze_readability.py

# 仅输出问题列表
python3 scripts/analyze_readability.py --input article.txt --issues-only
```

脚本输出内容：
- 基础统计（字数、句数、段数、阅读时间）
- 句子质量分析（长句列表、句长分布）
- 高频词与重复词组
- 填充词/被动句/冗长表达检测
- 可读性评分
- 改进建议列表

### 步骤 3：AI 深度分析

基于脚本输出的量化数据，进行深度语义分析：

#### 3.1 结构分析
- 开头是否吸引读者？
- 段落之间是否有逻辑过渡？
- 结尾是否收束有力？
- 是否有偏离主题的内容？

#### 3.2 表达分析
- 哪些句子可以更简洁？（给出修改前后对比）
- 哪些词汇可以替换为更精确的表达？
- 是否有歧义或模糊表述？
- 语气是否适合目标读者？

#### 3.3 可读性分析
- 对非专业读者是否友好？
- 专业术语是否需要解释？
- 信息密度是否合适？（太密则难读，太疏则浪费时间）

### 步骤 4：生成分析报告

按照以下结构输出报告：

```
📊 文本可读性分析报告
━━━━━━━━━━━━━━━━━━━━━━━━━━

字数：2,345 字 | 句子：89 句 | 段落：15 段
预计阅读时间：约 8 分钟

📈 可读性评分：78 / 100（B级：良好）

📋 分项评分：
  句子长度合理性  ███████░░░  75/100
  句子变化性      ████████░░  82/100
  段落结构        ███████░░░  70/100
  词汇丰富度      ████████░░  85/100
  表达简洁度      ██████░░░░  65/100

⚠ 发现的问题：
  1. 5个长句超过40字（最长72字），建议拆分
  2. "进行"出现12次，可替换为更具体的动词
  3. 第3段过长（380字），建议拆分
  4. 3处被动句，可改为主动语态
  5. "在...方面"出现4次，可精简

💡 改进建议：
  ...具体修改建议...
```

### 步骤 5：提供润色示例（如用户需要）

针对发现的问题，给出具体的修改示例：

**原句**（68字，过长）：
> 我们在进行项目管理的过程中，需要对各个部门之间的沟通协调机制进行系统性的优化和完善，以便能够在确保项目按时交付的同时，也能够有效地控制项目的整体成本和风险。

**修改后**（35字，更简洁）：
> 项目管理中需优化跨部门沟通机制，以确保按时交付、控制成本与风险。

## 五、文体适配标准

### 5.1 公文/正式报告
- 平均句长可偏长（25-40字），但需逻辑清晰
- 专业术语可保留，但需首次出现时解释
- 填充词「进行」「相关」「开展」可适当使用（正式语体需要）
- 评分基准：严谨 > 简洁

### 5.2 学术论文
- 句子可长，但需结构严谨
- 被动句和客观表达可接受
- 专业术语必须准确
- 评分基准：准确 > 简洁

### 5.3 公众号/新媒体文章
- 平均句长 15-25 字，短句为主
- 段落不超过 150 字，多分段
- 少用专业术语，多用口语化表达
- 评分基准：易读 > 严谨

### 5.4 技术文档
- 句子简洁明确，每句一个信息点
- 多用列表、步骤、代码块
- 避免歧义，精确描述
- 评分基准：准确 > 文采

### 5.5 商业文案/营销
- 短句为主，节奏感强
- 情绪化和感染力优先
- 少用填充词和被动句
- 评分基准：有力 > 完整

## 六、常见场景处理

### 场景 1：公众号文章润色
**用户**：粘贴一段公众号文章，说「帮我看看这篇文章写得怎么样」
**处理**：完整分析 → 评分 → 定位长句和长段落 → 给出拆分建议 → 提供修改示例。

### 场景 2：报告/公文检查
**用户**：粘贴一段工作报告，说「帮我检查一下这段公文」
**处理**：按公文标准分析 → 重点检查措辞是否正式、逻辑是否清晰 → 给出修改建议。

### 场景 3：邮件优化
**用户**：「帮我看看这封邮件写得行不行」
**处理**：分析语气是否得体 → 是否过长 → 关键信息是否突出 → 给出精简建议。

### 场景 4：写作教学
**用户**：「帮我分析一下这段学生作文的问题」
**处理**：全面分析 → 标注具体问题位置 → 给出教学式建议 → 提供改写示例。

### 场景 5：快速字数/时间查询
**用户**：「这段文字多少字？读多久？」
**处理**：仅输出基础统计（字数、句数、阅读时间），不做完整分析。

## 八、注意事项

1. **量化是辅助，语义是核心**：脚本提供数据，AI 做语义判断。不要仅凭数字下结论。
2. **文体适配**：不同文体对句长、正式度的要求不同，评分标准需按文体调整。
3. **不改变原意**：润色建议应保持作者原意，仅改善表达，不改变观点。
4. **中文分词局限**：脚本基于规则分词，可能不够精确。AI 需结合上下文修正。
5. **不替代编辑**：本技能提供参考建议，最终修改由用户决定。
6. **长文本处理**：超过 5000 字的文本，分段分析，避免遗漏。
7. **隐私保护**：分析过程中不存储文本，仅在当前会话中处理。
8. **客观中立**：评分基于通用可读性标准，不做主观审美判断。
9. **中英混排**：对中英混排文本，中文按字、英文按词分别统计后合并。
10. **不过度修改**：问题应聚焦真正影响可读性的地方，不为了改而改。

## 十、使用示例

### 示例 1：分析一段文章
**用户**：粘贴一段文章，说「帮我看看这段文字写得怎么样」
**AI**：运行脚本分析 → 生成评分和问题列表 → 给出具体修改建议 → 提供修改前后对比。

### 示例 2：检查公文
**用户**：粘贴一段工作报告，说「帮我检查一下这段公文」
**AI**：按公文标准分析 → 检查措辞、逻辑、正式度 → 给出修改建议。

**用户**：「这段文字多少字？读多久？」

**AI**：分别分析两版 → 对比评分变化 → 指出改进点和可能的不足。
